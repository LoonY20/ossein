# Ossein v0.2.0

Ossein v0.2.0 ships the first production module — a cache boundary designed
for real failure modes — completes multi-process migration safety for all
three SQL dialects, and introduces experimental generated service wiring.

## Highlights

### Cache module

- backend-neutral `cache.Store` contract: byte-oriented `Get`/`Set`/`Delete`
  with explicit miss, key, and TTL errors and defined buffer ownership;
- concurrency-safe in-memory driver: concurrent read locks, bounded amortized
  TTL cleanup on reads and writes, explicit `PurgeExpired`, and value copy
  isolation;
- typed JSON helpers and fail-open remember helpers: cache degradation falls
  back to the source of truth, incompatible cached JSON self-heals, context
  cancellation and loader errors always propagate, and `WithErrorHandler`
  keeps degraded caches observable;
- a documented strategy reserves backend-specific atomic features for
  optional capability interfaces, keeping third-party `Store` implementations
  source-compatible.

### Data layer

- SQLite migrations now serialize across processes through per-migration
  `BEGIN IMMEDIATE` transactions with bounded `PRAGMA busy_timeout` waiting,
  joining the PostgreSQL and MySQL locks shipped in v0.1.0;
- real SQLite lock-timeout and concurrent-runner integration tests run in CI;
- the new [database tooling guide](../DATABASE.md) documents sqlx, sqlc, and
  native pgx integration patterns, backed by a CI-compiled example module.

### Experimental: generated service wiring

`ossein wire` writes `internal/wiring/wiring_gen.go` with explicit
constructor calls in dependency order — a `Services` struct built without any
container reflection. Output is deterministic and gofmt-formatted, and the
generator rejects registrations it cannot express (closures, methods,
generics, unexported symbols, package-main declarations) with precise errors.
The service container remains the default path; the command may change or be
removed before v1.0 depending on real-world feedback.

Ossein core continues to have no third-party runtime dependencies.

## Install

Install the CLI:

```bash
go install github.com/LoonY20/ossein/cmd/ossein@v0.2.0
```

Add the framework to an existing Go module:

```bash
go get github.com/LoonY20/ossein@v0.2.0
```

## Quality

- CI runs formatting, vet, CLI builds, the full race detector, and the
  compiled database tooling example;
- PostgreSQL 17, MySQL, and SQLite concurrency behavior is covered by real
  integration tests;
- total statement coverage remains above the enforced 85% floor.

## Stability

This is a pre-1.0 release. Public APIs may evolve as Ossein is validated in
real applications. Production use should be evaluated carefully.

See the [roadmap](../ROADMAP.md) for what comes next: queues and workers,
additional cache drivers, and multi-service workspaces.
